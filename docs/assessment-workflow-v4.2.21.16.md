# Slugfester Decomposed Consensus Contract v4.2.21.16

The partition lane now separates score-blind inventory curation from performance judgment. This is an AI-only workflow, but it assigns semantic decisions to isolated AI passes and assigns chronology, legal ranges, identity, and scoring order to deterministic repository code.

## Stage 1: score-blind inventory lock

One 5.6 Sol curator receives the complete, unreduced candidate-evidence bundle. It defines the two burden routes, four to six weighted sections, one or two selected moves per side in every section, each selected candidate ID, a global constructive-or-reply classification, and a precise proposition.

The curator cannot see or emit response topology, ratings, calculated totals, winner labels, another judgment, legacy assessment prose, or scores. Candidate side, speaker, source span, attribution confidence, and attribution basis remain repository-owned. The repository orders the selected moves by source chronology and rerenders one source-exact evidence excerpt for every locked move from the original locally stored transcript events.

An inventory is rejected if weights do not total 100, a candidate or move ID is duplicated, a section lacks either side, or a reply has no earlier selected opposing move. No automatic target repair or semantic normalization is permitted.

## Stage 2: two independent judgments

Pass A and Pass B receive byte-identical locked inventories and separate role identities. Neither can change the candidate selection, routes, sections, propositions, chronology, attribution, or source evidence, and neither can see the other's output.

The judgment schema is generated after the inventory is locked:

- `moveJudgments` has one required property for every locked move and permits no additional move.
- Every reply component's target enum contains only earlier opposing locked move IDs.
- Constructive moves have no target fields.
- Diagnostic-defeat and justified-reframe responses require a structurally present contacted anchor, so their contact requirement cannot conflict with the selected response mode.
- The response class is repository-derived. The judge supplies only a 0–100 position within that class; the repository maps it to the legal absolute responsiveness range.
- Burden contact uses a repository-generated code that resolves to exactly one legal bridge, tier, and polarity, or to no contact. The judge supplies only a 0–100 position within that tier; the repository maps it to the legal absolute relevance/burden range.
- Untested charity is structurally fixed at the neutral 75 anchor. Tested charity requires an alternative interpretation and decisive qualification.
- The burden-completion adjustment is a residual only. The repository applies the proposed value only when all distinctness, burden-effect, nonduplication, burden-ID, move-ID, and explanatory-evidence conditions are satisfied; otherwise it applies zero.

Each judgment is compiled into the unchanged v4.2.20 raw-ledger contract and must pass its full source, chronology, response, anchor, charity, and burden validation. The compiler performs deterministic derivation, not semantic repair.

## Consensus and score order

After two valid judgments, the workflow must perform deterministic field-level disagreement extraction. Every medium-confidence move must receive audio verification before adjudication. A third isolated 5.6 Sol pass may adjudicate only disputed fields and may see only the evidence necessary for those fields. Final raw ledgers are assembled only after adjudication, and scores are derived in one deterministic pass only after the final ledgers validate.

The inventory curator is not one of the two performance judges. It is a score-blind coverage and structure pass. Pass A and Pass B are the two independent Sol assessments required by the consensus workflow.
