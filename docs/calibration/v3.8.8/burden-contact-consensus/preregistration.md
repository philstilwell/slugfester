# v3.8.8 Burden-Contact Consensus Preregistration

## Purpose and boundary

This score-free stage assigns one complete burden-contact tuple to every retained move in the three-debate v3.8.8 gate. It uses the locked 81-move coverage inventory and immutable section-and-weight plans, but it does not assess response quality or participant performance and cannot generate scores or prose.

## Exact inheritance rule

A v3.8.3 two-vote tuple may be carried forward only when the exact move ID survives and its debate identity, atomic excerpt, source span, speaker, side, proposition, route bridge ID, bridge tier, and bridge description remain unchanged. The audit found nine eligible moves, three per debate. Three earlier moves do not survive under the same identity and their tuples are not transferred to replacement material. Inherited tuples are locked and unavailable to the new classifier contexts.

## New classifications

The remaining 72 moves—25 in Debate 55, 22 in Debate 103, and 25 in Debate 161—receive two independent isolated 5.6 Sol classifications at high reasoning. Each move has the same complete 21-state universe: no contact plus support and attack for each of the ten route bridges. Anonymous option positions differ between passes while semantic content remains identical.

Each context receives the verified full local transcript and timestamped events. All 81 final moves have high-confidence speaker attribution; therefore no pending audio verification exists. Any later medium- or low-confidence move would be blocked until local audio verification is completed.

## Consensus and adjudication

A deterministic extractor will decode anonymous option IDs and compare complete tuples. Matching tuples receive two-vote consensus. Only disputed moves may enter a separately frozen third isolated pass. The adjudicator may select only one of the two anonymous initial tuples, receives neither pass identity nor initial rationale, and cannot invent a third value. Every final tuple must have two matching votes.

The nine inherited tuples and 72 newly resolved tuples will form one 81-move ledger only after all disputes are resolved. Scores remain blocked until that ledger validates.

## Transport, cost, and stop rules

The initial phase contains exactly six sequential model contexts, one pass per debate for each of two passes. Each context receives one inference attempt, no output retry, and a 60-minute timeout. Same-request stream recovery is recorded but never creates a second inference. Authentication uses the user's ChatGPT subscription with API keys removed. Maximum metered model API and transcription cost is $0.

Any source-hash mismatch, preexisting output, invalid context, unverified attribution, malformed candidate universe, or unresolved tuple stops progression. This stage cannot authorize numerical participant scoring, assessment prose, production mutation, the ten-debate gate, or the 195-debate rollout.
