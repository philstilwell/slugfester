# v2.2.2 route/section plan successor development contract

## Scope

This contract prospectively divides candidate-census planning into two score-blind model stages without changing the final plan semantics. It does not retry the failed v2.2.1 gate, accept any of its nine valid partial plans, extend Debate 75's timeout, execute a model, prepare side selectors, derive a score, promote the proposed v2.2 score policy, reclassify any failed gate, or authorize production mutation.

The route stage receives one debate's frozen inventory source packet, complete candidate census, inventory manuals, this guide, and a strict route-only schema. It authors only the two burden routes and their bridges. Sections and candidate selection are unavailable.

After a route output passes strict validation, the section stage receives the same frozen score-blind sources plus the immutable route output and a strict section-only schema bound to the canonical route hash. It authors only four to six weighted issue sections totaling exactly 100 percent. Candidate selection remains unavailable.

Repository code alone composes the two outputs into the unchanged v4.2.21.16.5 candidate-census plan and replays its complete deterministic validator. A binding mismatch, unknown field, invalid route, invalid section, non-100 weight total, contamination, or source-hash drift fails closed.

## Preserved boundaries

Every later model context remains bound to 5.6 Sol with low reasoning effort, ChatGPT-subscription authentication, API keys removed, one fresh isolated context per debate and stage, score blindness, one attempt, no retry, no timeout extension, and inventory concurrency at most two.

Legacy assessments, scores, winners, tags, publication prose, other debates, prior judgments, failed-gate execution metadata, the other planning-stage output before its required dependency, and candidate evidence excerpts remain unavailable.

The nine valid v2.2.1 plan outputs may be used only for model-free split/recomposition regression. They cannot satisfy any v2.2.2 gate. Debate 75 has no reusable plan output.

## Evidence limits

The v2.2.1 timeout occurred on a smaller-than-maximum packet, so input size is not established as its cause. Splitting the writable task reduces output complexity but does not guarantee model completion. Any later execution requires its own frozen packets, preparation manifest, explicit activation, cost estimate, and complete fresh-gate acceptance rule.
