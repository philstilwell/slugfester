# Slugfester Chronology-First Fresh-Six Workflow v4.2.3

This prospective gate inherits the complete v4.2.1 judgment, source-integrity, compact-transport, consensus, audio, scoring, compression, and acceptance contract, with only the v4.2.2 chronology-first output topology replacing nested section move arrays.

## Fresh disjoint sample

Repository code selects six dyadic debates from the frozen source-only metadata pool after this workflow, validator, schema fixture, and selector are committed. It excludes every debate previously retired or used in development or calibration, including all v4.1.7, v4.1.8, v4.1.9, v4.2.1, and v4.2.2 identities. No legacy score, critique, winner, tag, publication prose, or prior judgment may enter selection.

The sample contains one debate from each predeclared family: resurrection/history, morality/ethics, mind/agency, evil/hiddenness, science/origins, and general theism/religion. It includes at least one debate under 90 minutes, one from 90 through 120 minutes, and one over 120 minutes, with no more than three over 120. A fixed v4.2.3 salt ranks only family and debate ID; deterministic dynamic programming minimizes aggregate within-family rank with a stable family-order ID tie break.

## Primary judgment

Each original transcript, normalized event file, and local manifest remains stored and hash-locked. One lossless JSONL ledger `[eventIndex,startMs,durationMs,text]` must replay exactly to the original events. Each isolated Sol/low judge receives only the full v4.0, v4.0.1, and v4.1 rubrics, a consolidated v4.2.3 manual, the source-only packet, schema, and complete compact ledger.

Section metadata contains no nested moves. The judge emits one top-level move inventory strictly ordered by source event indices, with `sectionId` and `side` on every move. Each section still has one or two moves per side. Every reply may target only a selected move already emitted earlier. Repository validation independently rechecks ordering and target chronology before applying every inherited response, burden, charity, adjustment, rating, source-span, excerpt, and attribution rule.

Every context receives one attempt, no retry or normalization, and a 30-minute limit. A source, transport, schema, chronology, target, excerpt, or inherited validation failure stops the gate. Repository code alone compiles milliseconds after validation.

## Downstream order and acceptance

After all primaries pass, trigger values are calculated but not serialized as scores. Every medium- or low-confidence attribution requires audio verification before Pass B. Triggered and control debates receive isolated Sol/high review; disagreements are extracted deterministically and a third isolated pass adjudicates only disputed supplied candidates. All six receive a score-blind compression audit. A final scoring-input ledger locks before the only scoring pass. Legacy material remains inaccessible until scores lock, and AI Extension material remains outside participant judgment.

The gate passes only when all six sources, primary outputs, audio duties, reviews, disagreements, adjudications, compression audits, final ledgers, scoring replay, legacy thresholds, and the 52-hour central/60-hour conservative 195-debate projection pass. A failure is preserved unchanged. A pass authorizes preparation—not execution—of a preregistered held-out end-to-end gate. The 195-debate run remains unauthorized pending that held-out gate and explicit editorial promotion.
