# Slugfester production-canary independent-judgment packet workflow

## Scope

Prepare and freeze two isolated score-blind performance-judgment contexts, Pass A and Pass B, for each of the ten production-canary debates. This stage is deterministic and local. It does not run a judgment model, access audio, extract disagreements, adjudicate fields, derive scores, reconstruct publication prose, or mutate production records.

The passed inventory analysis is the authority for the ten debate identities and locked inventories. The production source-preparation manifest remains authoritative for each canonical local transcript chain. A missing source, hash mismatch, identity mismatch, non-dyadic debate, changed inventory, invalid reply chronology, unsupported response-schema keyword, pairwise inventory mismatch, or transport-ceiling breach stops preparation.

## Frozen model and isolation boundary

- Preserve the exact model label `5.6 Sol`, slug `gpt-5.6-sol`, and low reasoning effort.
- Preserve ChatGPT-subscription authentication with a maximum metered API cost of `$0` for preparation.
- Give each future context only the consolidated judgment manual, one source packet, one pass-specific judgment packet, and one pass-specific closed response schema.
- Keep the other pass, every other debate, candidate-selection material, legacy assessments, scores, winners, tags, Overall Commentary, AI Extension, and publication prose unavailable.
- Embed byte-identical canonical locked-inventory content in Pass A and Pass B. Only reviewer identity and pass-specific schema constants may differ.
- Do not create judgment, raw-output, validation, provenance, disagreement, audio, adjudication, score, publication, or production-mutation artifacts in this stage.

## Deterministic packet contract

Use the promoted v4.2.21.16 decomposed-consensus contract and the consolidated isolated-judgment manual proven by the hard-route gate. Repository code generates every legal reply-target enum from earlier opposing locked moves, derives response class and absolute responsiveness, maps relevance inside the selected burden tier, derives precision and calibration from closed findings, applies the fixed untested-charity anchor, and enforces the strict residual-adjustment exclusion rule. The model cannot author aggregate scores. To keep the largest production contexts under the proven transport ceiling, remove only non-validating JSON Schema `description` annotations; preserve every schema keyword, required field, constant, enum, bound, and all corresponding manual instructions.

Rebuild the v4.2.20 source packet from the canonical local `transcript.txt`, `events.json`, and `manifest.json` chain plus the complete compact ledger. Verify the complete source chain and the locked inventory before serialization. Remove the unsupported `uniqueItems` response-schema keyword while retaining deterministic runtime uniqueness validation. Keep every future model context at or below the proven 115,000-byte copied-input ceiling.

## Freeze and authorization boundary

The preparation manifest freezes all source and control hashes, every generated source packet, both judgment packets and schemas per debate, canonical inventory hashes, input sizes, future output paths, model identity, authentication, isolation claims, and stop rules. Passing deterministic fixtures authorizes only preparation of a separate independent-judgment execution manifest. Model execution remains unauthorized until that later manifest is separately defined, reviewed, and frozen.
