# Slugfester Bounded Lean Workflow v4.1.2

This prospective amendment inherits v4.1 and v4.1.1 except for primary reasoning effort and chronology ownership.

## Repository-derived chronology

The model no longer supplies a move sequence number. Every selected move already supplies a source event interval. Repository code flattens nested section moves and orders them by `sourceSpan.startEvent`, then `sourceSpan.endEvent`, then `moveId`. Response targets must precede the reply in that derived order.

This removes a redundant ordinal choice without changing any selected proposition, section, source span, response component, rating, burden contact, or score. The primary output remains bounded to eight through twenty-four moves and one or two actual moves per side in each of four through six sections.

## Primary model allocation

The bounded primary context uses 5.6 Sol at low reasoning effort. Triggered Pass B and candidate-bound adjudication retain 5.6 Sol at high reasoning effort. Complete transcript and timestamped-event access remains mandatory for every primary context.

The lower primary effort is acceptable only if the retired gate preserves winner classifications, stays within five points per final side after required triggered review, and passes the measured compute ceilings. Any quality trigger still forces the high-effort branch.

The v4.1.2 central plan assumes 5.5 primary minutes and projects 41.95 aggregate hours. The conservative plan assumes 7.0 primary minutes and projects 52.06 hours. After the gate, measured time replaces 5.5 minutes centrally; the conservative primary value becomes the greater of 7.0 minutes and 125% of the measured mean.
