# Slugfester adjudicated-consensus production workflow

## Scope and provenance

Apply this workflow only to dyadic debates: one substantive interlocutor per side. The corpus disposition manifest is authoritative; preserve 3+ speaker debates unchanged and report them as excluded rather than forcing them through a dyadic schema.

Use 5.6 Sol with low reasoning effort through the user's ChatGPT subscription for judgment and publication contexts. Use fresh isolated contexts, remove API keys from the inference environment, record actual model/authentication metadata, and never relabel work generated by another model. Paid transcription is a fallback only after a cost estimate and explicit approval.

## Source gate

1. Require local canonical `transcript.txt`, `events.json`, and `manifest.json` files under `.assessment-cache/captions/<videoId>/`.
2. Verify every recorded SHA-256 hash before semantic work. If public captions are inadequate, use the `transcribe` skill, preserve absolute timestamps, retain raw output in ignored storage, and save the normalized transcript locally.
3. Confirm exactly two substantive speakers. Stop on attribution ambiguity or a 3+ speaker format.
4. Keep legacy scores, critiques, tags, winners, Overall Commentary, and AI Extension out of all judgment contexts.

## Adjudicated-consensus stages

1. Build a score-blind burden map and chronological candidate inventory from the complete transcript.
2. Lock the final move inventory, source spans, section membership, burden bridges, and importance values before scoring.
3. Run two independent 5.6 Sol judgments per debate against the same blinded packet. Each pass scores only the locked semantic dimensions and supplies rationales; neither sees the other pass.
4. Extract disagreements deterministically. Treat categorical differences, decision-option differences, response-component differences, and preregistered numerical deltas as disputes.
5. Audio-verify every below-high-confidence move before adjudication. Medium confidence always triggers audio verification.
6. Run a third isolated 5.6 Sol context on disputed fields only. Give it the source evidence and anonymous initial options, not pass identities, scores, winners, other debates, or legacy assessments. It may select only an existing option unless the frozen field schema explicitly permits a source-grounded correction.
7. Assemble and validate the final ledger. No unresolved dispute or required audio check may remain.
8. Derive all move, section, and overall scores once, in repository code, after adjudication. Never ask the model to author totals and never hand-adjust a calculated score.

## Publication reconstruction

After scores lock, run one isolated publication context per debate. It receives the locked source packet, final judgments, calculated score bands, reference catalog, and display contract; it cannot change identity, structure, move selection, or scores.

- Summary target: 18–28 words; accept 8–35.
- Representative quotation target: 6–14 words; accept only a 3–18 word exact substring from a quote-eligible source span.
- Critique target: 112–118 words. Accept 105–130 words, at least 880 characters, exactly four sentences in this order: `Strongest feature:`, `Principal limitation:`, `Live burden:`, `Locked score:`. Require terminal punctuation and reject unexpected CJK/Hangul or replacement characters. Do not impose a maximum-character transport constraint.
- Preserve tags only when the named defect materially applies; prefer no tag to a forced tag.
- Include Overall Commentary for both sides from the locked record.
- Immediately after it, include a visibly distinct native `details` accordion titled `AI Extension`, collapsed by default. State clearly that it is an AI contribution and does not affect scores. Give each side a strengthened final argument plus genuinely new reinforcing arguments. Do not use the word `unassailable`.
- Display exactly: `Assessments made by 5.6 Sol. — Rubric: Slugfester Reassessment Rubric v2.`

Partition invalid publication fields into isolated repair packets with at most two writable fields. Permit one attempt per packet and no recursive automatic retry. Revalidate the complete debate after merging; a failed repair stops that debate.

## Validation and staging

For every debate, replay source hashes, the full semantic validator, the one-pass score calculator, exact quotations, prose integrity, AI Extension disclosure/novelty, and deterministic compilation. Inspect desktop and 390-pixel mobile rendering, accordion pointer and keyboard behavior, horizontal overflow, and console errors before production mutation.

Run the campaign in stage batches using the frozen manifest and tested concurrency: discovery 4; inventory 2; judgments 2; audio 2; adjudication 2; publication 2. Begin with a ten-debate production checkpoint. Stop on a source failure, isolation failure, unresolved audio/dispute, invalid ledger, model-authored score, non-exact quote, failed repair, rendering regression, or projected schedule above the approved bound.

Production records and rankings may change only after each debate independently passes every gate. Commit and push completed validated batches with their ledgers, source provenance, execution manifests, and audit summaries.
