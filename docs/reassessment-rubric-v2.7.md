# Slugfester Reassessment Rubric v2.7

This classification-only rubric makes target scope and burden orthogonal to target object, and makes diagnostic impact an explicit link to a locked object. It retains the v2.6 component graph/contact rules and the stable burden/reframe rules.

## Step 1: target object

Choose `same` unless the response answers a different subject, referent, comparison class, baseline, or question type. A bad answer, weak answer, narrower answer, modal answer, or unsupported answer is not a changed object merely because it fails.

Choose `changed` only with the shortest exact phrase showing the new object and one change type: `subject`, `referent`, `comparison-class`, `baseline`, or `question-type`.

## Step 2: target scope

Choose:

- `same` when strength, temporal range, quantification, and modality are unchanged;
- `narrowed` when the response restricts the proposition's range, strength, time, population, or conditions;
- `strengthened` when it replaces the proposition with a materially stronger commitment; or
- `modality-shift` when it changes possibility, probability, actuality, necessity, or certainty.

A scope change keeps the object available for component annotation. Cite exact scope evidence. At least one affected component must receive `qualifies` or `distinguishes`; otherwise the scope judgment is unsupported.

## Step 3: target burden

Choose:

- `retained` when the response continues to answer the live demand;
- `reassigned` when it moves that demand to another party; or
- `replaced` when it answers a materially different demand.

Reassignment or replacement requires exact evidence and derives substituted disposition. A critical side is not reassigned an affirmative contrary burden unless it explicitly adopts one.

## Step 4: typed component operation

When target object is `same` and burden is `retained`, annotate every target component:

- `accepts`: grants or relies on the component;
- `denies`: asserts that the component is false;
- `distinguishes`: splits a term, case, scope, or referent in a way that directly changes the component;
- `qualifies`: narrows, weakens, conditions, or limits the component;
- `explains`: supplies a mechanism or reason directly accounting for the component;
- `undermines`: attacks the component's warrant, inference, comparison, or evidential force without directly denying it; or
- null: performs none of these operations.

Every positive operation requires exact response evidence. Contact never propagates to dependencies or dependents. Collective language contacts multiple nodes only when its grammatical and argumentative scope expressly covers each node.

Relevant contrary material is available only for a same-object, retained-burden target with no component operation, and it requires exact evidence.

## Step 5: diagnostic object and defect

Diagnostics apply only to responsive moves. First identify what is criticized:

- `target-component`: one locked component ID; or
- `target-packet`: the target argument as a whole.

Then choose the narrowest expressed defect:

- `contradiction`: jointly asserted commitments cannot all be true;
- `missing-premise`: a required supporting proposition is absent;
- `ambiguity`: a term, scope, referent, or reading shifts or remains unresolved;
- `invalid-inference`: the conclusion does not follow even if premises are granted;
- `unsupported-comparison`: a comparative conclusion lacks an adequate baseline or rival comparison;
- `irrelevance`: the offered consideration does not bear on the identified target conclusion or burden;
- `evidential-insufficiency`: the response expressly says the evidence does not warrant the identified claim;
- `scope-mismatch`: the target demands or concludes more than the motion or stated proposition covers;
- `attribution-error`: the target assigns a claim the respondent expressly disowns; or
- `none`: no qualifying defect is explicitly diagnosed.

`none` requires a null object and null defect evidence. There is no `other` category.

## Step 6: impact mode

Choose:

- `none`: no impact statement;
- `verdict`: a bare judgment such as wrong, absurd, inadequate, or unpersuasive; or
- `inferential-consequence`: an exact statement of what the defect does to the locked object, inference, conclusion, or burden.

Omission language, ridicule, analogy, motive criticism, and “not good enough” do not by themselves state an inferential consequence. An analogy can qualify only when the speaker expressly draws the relevance or inferential lesson.

The diagnostic flag is calculator-derived and true only for a non-null defect and object with exact defect evidence plus an exact `inferential-consequence` impact.

## Coverage anchors

- `full`: qualifying operation on every component;
- `partial`: operation on some but not all components;
- `relevant-nonanswer`: no operation, but exact relevant contrary material;
- `nonanswer`: same object and retained burden, but neither operation nor qualifying contrary material;
- `substitution`: changed object or reassigned/replaced burden; and
- `not-applicable`: constructive move.

Do not work backward from a desired responsiveness band.

## Multi-speaker ownership

Every move belongs to its actual speaker. Every responsive target names its actual target speaker and side. A teammate's claim remains speaker-only unless another teammate explicitly adopts it in a locked adoption record. Side-level burden contribution never transfers individual argumentative credit.

## Stable anchors and numerical stop

Apply v2.6 component graph, exact evidence, target recency, reframe, eligible bridge, and bridge-tier rules unchanged. No v2.7 classification artifact authorizes numerical scoring.
